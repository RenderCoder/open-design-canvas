## Guardrails

- 先运行 `bd show <id> --long`，完整阅读本任务，再运行 `bd update <id> --claim`。
- 不要只根据文件名猜测；必须用 `rg` / `find` / `sed` / `cat package.json` 检查当前 fork 的真实结构。
- 每个 bead 只做自己的范围。发现跨范围工作时，用 `bd create` 建新任务，或用 `bd update <id> --notes` 记录。
- 不提交密钥、OAuth token、私有 Figma file ID、真实客户设计内容。
- Figma-native 能力优先使用 Figma Remote MCP；不要自研 REST API 写画布路径。
- 任何 prompt/skill 变更都要保留现有 Open Design 工作流的兼容性。

## Acceptance criteria

- Docs are linked from README or an obvious docs index.
- A new contributor can run mocked flow without Figma credentials.
- Relevant docs/tests are updated or an explicit reason is recorded.
- Validation command results are written to bead notes.
- If acceptance is met, close with `bd close <id> --reason "Completed: ..."`.

## Suggested verification

- Run the smallest relevant tests discovered in A03.
- For prompt/skill metadata changes, add or update fixture/snapshot tests where possible.
- For UI changes, use mock data first; real Figma is optional unless this task explicitly says otherwise.
- End by running `bd ready --json` and recommend the next unblocked task.
